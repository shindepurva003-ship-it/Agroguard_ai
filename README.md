# AGROGUARD AI — Avishkar prototype

A low-cost, software-first research prototype for crop suitability, water-balance estimation,
and transparent climate-risk screening. It is an educational decision-support prototype,
not a substitute for a soil test, local agricultural expert, or official weather advisory.

## Quick start

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS/Linux:
source .venv/bin/activate
pip install -r requirements.txt
streamlit run app.py
```

The app can run in **demo mode** using a clearly labelled illustrative dataset generated by
`src/data_utils.py`. For research results, obtain a real labelled Crop Recommendation CSV
and put it at `data/Crop_recommendation.csv`. Expected columns:
`N,P,K,temperature,humidity,ph,rainfall,label`.
The dataset must be documented in your report, and its licence/terms checked before redistribution.

## Research-grade use

1. Replace demo data with a documented real dataset.
2. Keep a hold-out test set; compare Decision Tree, KNN and Random Forest.
3. Report macro-F1, per-class precision/recall, confusion matrix and cross-validation.
4. Do not describe crop-classification output as yield prediction.
5. For irrigation, enter measured daily weather and crop coefficient values from a reliable source.
   The prototype uses a transparent simplified water-balance estimate, not a full operational
   irrigation prescription.
6. Climate risk is a rule-based screening indicator until validated labelled risk data exists.
7. Record local soil-test and field observations for validation across multiple agro-climatic zones.

## Data files

- `data/Crop_recommendation.csv`: optional real labelled crop dataset.
- `data/demo_crop_data.csv`: generated illustrative data, **not evidence** and not suitable for
  claiming research accuracy.
- `data/sample_farm_observations.csv`: blank schema for local validation records.

## Suggested 3-person split (under 2 weeks)

- Member 1: data provenance, cleaning, EDA, local observation plan.
- Member 2: model comparison, validation, SHAP/feature explanations.
- Member 3: irrigation/risk modules, Streamlit integration, testing and demo.
All members should review the full methodology and limitations.

## Important limitations

- A crop recommendation dataset may contain synthetic or narrow-region examples. Check provenance.
- Model confidence is not probability of crop success.
- Crop labels depend on dataset coverage; unseen crops/regions are not supported.
- The irrigation calculator is a simplified estimate and requires local calibration.
- Risk thresholds are configurable screening rules, not a validated disease/yield model.
